Getting Started

Basics

MongoDB is a document-oriented NoSQL database. Data lives in databases → collections → documents (BSON/JSON objects).

🔌Connection

# Start shell / connect to a host
mongosh "mongodb://localhost:27017"
mongosh "mongodb+srv://user:pass@cluster.mongodb.net/mydb"

# Common flags
mongosh --quiet --eval "db.stats()" mydb

🧭Core Hierarchy

show databases      // list DBs
show collections   // list collections
use mydb           // switch/create DB
db                 // current DB handle
db.getName()        // current DB name
Model: Database → Collection → Document → Field. Documents are BSON (binary JSON) with a unique _id.

Create / Insert

CRUD

Add new documents to a collection.

➕Insert

// Insert one document
db.users.insertOne({
  name: "Alice",
  age: 30,
  email: "alice@mail.com",
  tags: ["admin", "beta"]
})

// Insert many (ordered by default)
db.users.insertMany([
  { name: "Bob",  age: 25 },
  { name: "Carol", age: 28 }
], { ordered: false })

// Upsert: insert if not exists
db.users.updateOne(
  { email: "alice@mail.com" },
  { $set: { name: "Alice" } },
  { upsert: true }
)

💡Insert Notes

  • insertOne(doc) returns insertedId.
  • insertMany([...]) returns insertedIds map.
  • MongoDB auto-generates _id (ObjectId) if absent.
  • ordered:false continues past errors (faster bulk).
  • Duplicate _id → E11000 duplicate key error.
  • save() is deprecated — use insert/update.
  • Max document size: 16 MB.
Bulk: For large imports use mongoimport instead of loops.

Read / Query

CRUD

Retrieve documents with filters, cursors and options.

🔍Find

db.users.find()                 // all docs
db.users.findOne({ name: "Alice" })

// Filter + projection + options
db.users.find(
  { age: { $gte: 18 } },          // query
  { name: 1, age: 1, _id: 0 }     // projection
).sort({ age: -1 })
 .skip(10)
 .limit(5)
 .pretty()

// Counting
db.users.countDocuments({ age: { $gt: 25 } })
db.users.estimatedDocumentCount()  // fast, no filter

🖱️Cursor Methods

  • .toArray() — load all results into array
  • .forEach(fn) — iterate results
  • .next() — fetch next document
  • .count() — count (deprecated, use countDocuments)
  • .explain("executionStats") — plan details
Default batch: 101 docs first, then ~16MB per batch. Always .limit() in production code.
Anti-pattern: Skip is slow for deep pagination — use range/anchor pagination on _id.

Update

CRUD

Modify existing documents using update operators.

🛠️Update Methods

// Update one / many
db.users.updateOne({ name: "Alice" },
  { $set: { age: 31, city: "Pune" } })

db.users.updateMany({ age: { $lt: 18 } },
  { $set: { minor: true } })

// Replace whole document (keeps _id)
db.users.replaceOne({ _id: id }, { name: "New" })

// Find and modify (returns old/new doc)
db.users.findOneAndUpdate(
  { name: "Alice" },
  { $inc: { age: 1 } },
  { returnDocument: "after" }
)

⚙️Update Operators

OperatorAction
$setSet field value
$unsetRemove field {field:""}
$incIncrement / decrement
$mulMultiply
$renameRename field
$setOnInsertSet only on upsert-insert
$pushAdd to array (option $each)
$addToSetAdd if not present
$pullRemove matching array items
$popRemove first/last (1 / -1)
$pullAllRemove list of values
$currentDateSet to now (date/ timestamp)
Warning: Passing a plain object without operators replaces the whole document (except _id).

Delete

CRUD

Remove documents or entire collections.

🗑️Delete

db.users.deleteOne({ name: "Alice" })
db.users.deleteMany({ age: { $lt: 18 } })

// Drop entire collection (fast, removes indexes)
db.users.drop()

// Delete all docs (keeps collection + indexes)
db.users.deleteMany({})

// Drop whole database
db.dropDatabase()

📌Notes

  • Returns {acknowledged, deletedCount}.
  • deleteMany({}) is O(n) — prefer drop() to reclaim space quickly.
  • Deletes are logged in the oplog → replicate to secondaries.
  • Use explain() to confirm index usage before mass deletes.

Logical & Element Operators

Query

🧠Logical

db.users.find({
  $and: [
    { age: { $gte: 18 } },
    { city: "Pune" }
  ],
  $or: [
    { role: "admin" },
    { role: "owner" }
  ],
  $nor: [ { banned: true } ]
})

// Implicit AND: multiple keys in one object
db.users.find({ age: { $gt: 18 }, city: "Pune" })

🔎Element / Type

// Field exists (and not null)
{ email: { $exists: true } }

// Type check
{ age: { $type: "int" } }
{ age: { $type: ["int", "double"] } }

// Array length
{ tags: { $size: 3 } }

// Field not equal (handles missing fields)
{ deletedAt: { $eq: null } }
$type aliases: string, int, double, decimal, array, object, date, bool, objectId.

Projection, Sort & Paging

Query

🎯Projection

// Include only name & email
db.users.find({}, { name: 1, email: 1 })

// Exclude _id
db.users.find({}, { _id: 0, name: 1 })

// Nested fields
db.users.find({}, { address.city: 1 })

// Slice an array (last 3 tags)
db.users.find({}, { tags: { $slice: -3 } })

↕️Sort & Pagination

// 1 = ascending, -1 = descending
db.users.find({ active: true })
  .sort({ score: -1, name: 1 })
  .skip(20)
  .limit(10)

// Keyset pagination (fast, scalable)
db.users.find({ _id: { $lt: lastSeenId } })
  .sort({ _id: -1 }).limit(10)
Cannot mix include (1) and exclude (0) in projection — except _id.

Regex & Text Search

Query

🔡Regular Expressions

// Literal regex
db.users.find({ name: /^ali/ })        // prefix
db.users.find({ name: /alice/i })      // case-insensitive

$regex operator
db.users.find({ name: { $regex: "ali", $options: "i" } })

// Anchored prefix uses index efficiently
db.users.find({ email: { $regex: "^a.*@mail" } })

📝Text Search

// Create text index
db.articles.createIndex({ title: "text", body: "text" })

// Search
db.articles.find({ $text: { $search: "mongodb index" } })

// Phrase & negation
{ $text: { $search: "\"mongodb db\" -redis" } }

// With score
db.articles.find({ $text: { $search: "nosql" } })
  .sort({ score: { $meta: "textScore" } })

Aggregation Pipeline

Advanced

A pipeline of stages that transform documents — the SQL equivalent of SELECT … GROUP BY … JOIN.

📊Basic Pipeline

db.orders.aggregate([
  { $match:  { status: "paid", date: { $gte: start } } }, // filter FIRST (uses index)
  { $unwind: "$items" },                                // explode array
  { $group:  {
      _id: "$customerId",
      total:   { $sum: { $multiply: ["$items.price", "$items.qty"] } },
      orders:  { $sum: 1 },
      avgOrder:{ $avg: "$total" }
  } },
  { $sort:   { total: -1 } },
  { $limit:  10 },
  { $project: { _id: 0, customer: "$_id", total: 1, orders: 1 } }
], { allowDiskUse: true })
StagePurpose
$matchFilter documents (put early → index use)
$projectReshape / compute fields
$groupGroup by key + accumulators
$unwindDeconstruct array into rows
$sortOrder documents
$limit / $skipPaging / trimming
$lookupLEFT JOIN another collection
$addFields / $setAdd/modify fields in place
$countCount remaining docs
$facetRun multiple sub-pipelines in parallel
$bucket / $bucketAutoHistogram / range bucketing
$sampleRandom documents
$outWrite results to a collection
$mergeMerge results into target (upsert)
$graphLookupRecursive self-join (trees)
$replaceRootPromote sub-doc to root

🔗$lookup Example

{
  $lookup: {
    from: "users",              // collection (same DB)
    localField: "userId",
    foreignField: "_id",
    as: "user"
  }
},
{ $unwind: "$user" }   // or {$unwind: {path:"$user", preserveNullAndEmptyArrays:true}}

🪄Expression Operators

  • $sum, $avg, $min, $max — math in expressions
  • $concat, $toUpper, $substr — strings
  • $cond / $switch — conditionals
  • $multiply, $divide, $subtract — arithmetic
  • $ifNull — default value
  • $map / $filter / $reduce — array transforms
  • $dateToString, $dateTrunc — dates
  • $size, $slice, $isArray — array helpers
Tip: $match and $sort at the start can use indexes; later stages need allowDiskUse: true for large spills (100MB limit per stage).

Indexing

Performance

Indexes dramatically speed up reads but cost write throughput and storage.

⚡Create & Manage

// Single-field
db.users.createIndex({ email: 1 }, { unique: true })

// Compound (order matters: equality → range → sort)
db.orders.createIndex({ userId: 1, status: 1, date: -1 })

// Options
db.users.createIndex({ name: 1 }, {
  name: "name_asc",
  unique: false,
  sparse: true,              // skip docs missing field
  expireAfterSeconds: 3600,  // TTL index
  partialFilterExpression: { active: true }
})

// Manage
db.users.getIndexes()
db.users.dropIndex("email_1")
db.users.dropIndexes()

📦Index Types

TypeUse
SingleOne field lookups
CompoundMulti-field queries/sorts
MultikeyArray fields (auto)
UniqueEnforce distinct values
TTLAuto-expire (sessions, tokens)
SparseSkip missing/null fields
TextFull-text search
2dsphere / 2dGeoJSON location queries
HashedHash sharding
PartialIndex subset via filter

🔬Explain

db.orders.find({ status: "paid" })
  .explain("executionStats")

// Look for:
//   winningPlan: IXSCAN  (index)  ✅
//               COLLSCAN (full)   ❌
//   keysExamined ≈ nReturned (efficient)
//   totalDocsExamined (low is good)

📏Compound Index Rules

  • ESR rule: Equality → Sort → Range order.
  • Left-prefix: {a,b,c} serves a, a+b, a+b+c.
  • Won't serve b alone or a+c efficiently.
  • Direction only matters for sort (all -1 matches reverse).
  • One index per query — MongoDB picks one (or intersects).
  • Use hint("index_name") to force an index.
Write cost: Every index must be updated on insert/update. Avoid indexing rarely queried, low-cardinality fields (e.g. gender) unless selective.

Transactions

Advanced

Multi-document ACID transactions (require a replica set / sharded cluster).

🔁Session Example

const session = client.startSession();
try {
  session.withTransaction(async () =>
    async () => {
      await db.collection("accounts").updateOne(
        { _id: from }, { $inc: { balance: -100 } }, { session });
      await db.collection("accounts").updateOne(
        { _id: to },   { $inc: { balance: 100 } },  { session });
    });
  } finally {
    session.endSession();
  }
Notes: Read/write concerns apply per transaction; transactions are causal-consistent by default; keep them short — they hold WiredTiger snapshot resources.

Schema Design

Modeling

Unlike SQL, optimize for query patterns — "data that is accessed together should be stored together."

🧩Embed vs Reference

Embed (1:few / 1:1)Reference (1:many / many:many)
ReadsOne query ✅$lookup / multiple queries
WritesSingle-doc atomicMulti-doc updates
ConsistencyAlways consistentMay go stale
Growth16MB doc limitUnbounded
Rule of thumb: Embed if you always read together and the array is bounded. Reference if unbounded or updated independently.

🏗️Common Patterns

  • Bucketing: group time-series events into docs (e.g. 500 sensor readings each).
  • Subset: keep only last N references inline, the rest referenced.
  • Computed: store aggregates (denormalized counts) updated on write.
  • Polymorphic: one collection, fields vary by type (type discriminator).
  • Attribute: EAV-style for varying product attributes.
  • Snapshot: copy historical data (orders keep a product snapshot).
Avoid: Massive unbounded arrays — split into separate docs beyond tens of thousands of elements.

Admin & Backup

Ops

💾Backup / Restore

# Logical backup
mongodump  --uri="$URI" --out=./backup
mongorestore --uri="$URI" ./backup --drop

# Query subset
mongodump --db=mydb --collection=users --query='{"age":{"$gt":18}}'

mongoexport --db=mydb --collection=users --out=users.json
mongoimport --db=mydb --collection=users --file=users.json --headerLine

# Point-in-time backup: add --oplog to mongodump

🎚️Write / Read Concern

  • W: 1 (default ack by primary), majority, 0 (unacknowledged)
  • Journal: j: true — write persisted to journal
  • Read concern: local (default), majority, linearizable
  • Read preference: primary → primaryPreferred / secondary / nearest

Performance Tips

Best Practices

🚀Do

  • Put $match first in pipelines; filter on indexed fields.
  • Project only needed fields — less network, better plan-cache hits.
  • Follow the ESR rule for compound index order.
  • Use explain("executionStats") to verify IXSCAN.
  • Batch inserts; prefer bulk APIs over per-doc round trips.
  • Use TTL indexes for ephemeral data instead of cron deletes.
  • Monitor with db.currentOp(), db.serverStatus(), mtools, or Atlas metrics.
  • Profile selectively: db.setProfilingLevel(1, {ms: 100}).

🚫Avoid

  • Unindexed queries (COLLSCAN), especially on $lookup foreigns.
  • Deep skip() pagination.
  • Huge numbers of tiny documents — per-doc storage overhead.
  • Storing large binaries in documents (use GridFS).
  • Unbounded arrays & "one giant document" for high-write data.
  • Over-indexing — every index slows writes and eats RAM.
  • Calling toArray() on huge cursors (OOM).
  • Running distinct() on unindexed, high-cardinality fields.
GridFS: For files > 16 MB, use GridFS — chunks (default 255 KB) in fs.files and fs.chunks.
